# 验证记录

2026-11-22，Windows x64，Rust/Cargo 1.93.1，Gyan FFmpeg 9.0 full build。

## 自动检查

- `cargo fmt --all -- --check`
- `cargo clippy --all-targets -- -D warnings`
- `cargo test -- --include-ignored`，设置 `MEDIAFORGE_TEST_FFMPEG` 指向便携包内的 FFmpeg。
- `cargo build --release --locked`
- `git diff --check`

测试分层：

1. 单元：透明像素白底合成；音视频参数映射；原生暂停/恢复后 FFmpeg 进度文件停止/继续增长，以及关闭 Job Object 后挂起进程退出。
2. 集成：11 种图片格式实际写出再解码、缩放；保护原文件和已有输出；损坏文件不留最终输出；有界并发下同名不同扩展输入分别保存、失败不阻塞后续任务；暂停队列可取消。
3. 引擎链路：生成短视频和音频，FLAC 转 9 种音频格式并解码、有损格式转回 WAV；MP4 转 9 种视频封装和 GIF 并解码；无音轨视频可转视频，提取音频失败；正在转码的任务暂停后取消，回收子进程并删除临时输出。

## 真实桌面系统流程

使用便携包里的 `MediaForge.exe`，通过 Windows UI 自动化操作，样本均为生成的测试文件：

- 文件选择器打开包含中文和空格的 PNG 路径，选择 JPG，点击“开始转换”。窗口报告成功 1、失败 0，输出 JPEG 可解码。
- 同样从界面打开 FLAC，选择默认 MP3，成功输出可解码音频，转换期间无终端窗口。
- 从界面打开 20 秒 MP4，选择 WebM，开始转码，点击暂停，按钮变为“继续”；点击继续后最终报告成功，WebM 可解码。
- 初始状态和转换中控件禁用、输出路径提示、结果框、暂停/恢复按钮的视觉布局已检查。

拖放入口使用 Win32 `WM_DROPFILES`；本次真实桌面验证以文件选择器为入口，未自动化跨窗口拖拽。未在另一台全新 Windows 机器或所有 DPI 配置上运行。便携包依赖路径固定为相对可执行文件的 `engines/ffmpeg.exe`；主程序使用静态 C 运行库。

## 打包

打包脚本复制引擎、许可证、确切版本及配置说明、SHA-256 清单。原始依赖文件时间戳若早于 1980 年，仅调整打包副本时间，以符合 ZIP 格式。源码仓库忽略 `target/`、`dist/`，不会把测试音视频或 200+ MB 引擎二进制加入 Git。
